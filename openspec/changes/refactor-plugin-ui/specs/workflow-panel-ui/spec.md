## ADDED Requirements

### Requirement: 面板注册与页头

工作流面板 MUST 作为右侧栏的一种 tab 类型注册，kind 为 `dev-flow`，body 直接占用 tab strip 以下的整个区域并自行铺 `--dsw-alias-bg-base`。面板 MUST NOT 自绘标题行或第二层 tab strip：页头第一行就是五个页面的导航。

#### Scenario: 从引导卡片打开面板

- **WHEN** 用户从右侧栏「工作流」引导卡片进入
- **THEN** 面板以 `dev-flow` 停靠，顶部 38px 是五页导航与刷新键，导航之下直接是页面内容，没有额外的标题或面包屑

#### Scenario: 会话不在工作区根

- **WHEN** 会话的工作目录不是工作区根
- **THEN** 面板只提示打开根目录，不渲染任何列表

### Requirement: 五页导航与手动刷新

面板顶部有两层：最上一行 28px 是 shell 的 pane 标签，MUST 使用 dockkit 的 quiet 形态（13px `label-primary`、无底色、无关闭键、左侧标签图标），插件 MUST NOT 在这行再叠第二个控件行。第二层是 38px 页面导航行：一排 13px 文本标签，依序为概览、任务、槽位、基线、代理，选中项 `label-primary` + 500，其余 `label-tertiary`，标签 26px 高、R8、hover 用 `interactive-bg-hover`；MUST NOT 用 `SegmentedTabs` 之类的分段控件容器，MUST NOT 用卡片、胶囊或下划线指示器。导航行右端 MUST 依次放「最近刷新时间 + 28px 刷新图标键（配 `Tooltip`）」：时间是 12px `label-tertiary`，紧贴刷新键左侧 8px，五页都 MUST 有；MUST NOT 把刷新时间画进页面内容里（例如指标区底部）。导航行下沿 MUST NOT 画线：第一条带的带色边缘本身就是分隔。刷新后重新读取同一份 `.dev-flow/` 快照，面板 MUST NOT 轮询。

#### Scenario: 切换页面

- **WHEN** 用户在导航上点「槽位」
- **THEN** 内容区替换为槽位页，导航的选中指示器移动，其它页面状态保留

#### Scenario: 手动刷新

- **WHEN** 用户点刷新键
- **THEN** 快照重新读取，读取期间刷新键显示加载态，完成后页面内容整体替换而不是叠加

#### Scenario: 保持打开

- **WHEN** 面板保持打开十分钟且用户没有任何操作
- **THEN** 不发生任何定时读取

### Requirement: 概览页

概览页 MUST 是「指标摘要 + 未完成子面板 + 项目子面板」，全部用列表项，没有任何表格与列头；未完成与项目 MUST 是两个可折叠、可拖高度的子面板，指标 NOT 参与分区。

- **指标** MUST 是六格：子代理 `2/5`、活跃任务、待验收、项目、活跃槽位、基线改动。刷新时间 MUST NOT 出现在指标区（它在页头刷新键旁，见「五页导航与手动刷新」）。
- **活跃任务** 每项：状态点 + 任务名（后面可跟仓库的等宽后缀）+ 右侧状态词；悬停右侧换成「定位 / 删除」。排序固定 失败 → 待验收 → 待合入 → 开发中 → 等待。
- **项目** 每项：仓库图标 + 仓库名 + 右侧计数簇；顺序固定 开发 → 等待 → 验收 → 合入 → 失败，零项不写；悬停右侧换成「打开」。计数簇的写法 MUST 是「状态名 11px `label-tertiary` + 计数 13px/500 `label-primary`、tabular-nums」，名与数之间 5px、对与对之间 14px；失败那一对 MUST 只把数字染成 error 色（状态名仍是三级墨色）。MUST NOT 用彩色胶囊、MUST NOT 给计数加背景块。
- 三段段头 MUST 只有标题与计数，MUST NOT 放筛选、排序或动作控件。

#### Scenario: 概览首屏

- **WHEN** 用户打开概览页
- **THEN** 先看到六个数字，再看到未完成任务列表，最后是项目列表

#### Scenario: 一个仓库有多种状态的任务

- **WHEN** 某仓库同时有待验收、待合入、失败的任务
- **THEN** 该项目行右侧写「验收 1　合入 1　失败 1」：状态名小、数字大且等宽对齐，失败的数字是红色，三对间距 14px

### Requirement: 子面板（可折叠、可调整高度）

面板内容 MUST 组织成**子面板**：一页里的每个分区各自是一个子面板，而不是把段直接平铺在面板里。

- 子面板头部 MUST 照 DSH 的 disclosure 行：24px 高、标题 13/400、默认 `label-tertiary`、指针悬停升到 `label-secondary`（对象头如仓库名用 `label-secondary`、悬停升 `label-primary`）；右端一个 14px 箭头，展开向下、折叠向右；整行可点折叠，MUST NOT 只让箭头可点。头部 MUST NOT 有底色、加粗或分割线。
- 相邻子面板之间 MUST 有一个 7px 高的分隔条，且分隔条上 MUST 常显一条 0.5px `border-l3` 的细线——子面板的边界靠这条线交代，静止时也必须看得见；指针悬停或拖拽时线升为 `border-l2`。MUST NOT 用卡片、底色带或整段留白代替这条线。
- 拖动分隔条 MUST 只改变相邻两个子面板的高度，二者各不低于「头部 + 56px」，其余子面板高度不变。
- 子面板 MUST 可折叠：点头部后只剩 24px 一行、箭头转为向右；再点恢复上一次高度、箭头向下。
- 每个子面板的内容 MUST 在自己的区域内滚动，MUST NOT 把整页滚起来。
- 分区划分固定：概览 = 未完成 / 项目；任务 = 开发 / 验收；槽位 = 每个仓库一个子面板；基线 = 每个基线组一个子面板；代理 = 主会话 / 子代理。
- 顶部摘要（概览的指标、任务的调度行、代理的运行指标）MUST NOT 参与分区：它们不折叠、不可拖。
- **任务详情**与**基线编辑/新增** MUST 作为最后一块子面板参与分区（可折叠、可拖高度），MUST NOT 用固定不动的底部停靠区。
- 子面板的**顺序、高度比例、折叠状态** MUST 持久化到本地（按页面分区集合分组存 localStorage，键 `dev-flow:panels:group:<分区 key 用 | 连接>`）；重开面板或切页回来时恢复上次布局，页面上新增/删除分区时 MUST 保留已有分区的设定、把新分区接在末尾并默认展开；没有存档或存档不可解析时 MUST 回落到「按内容分配」的默认布局，不得报错。

#### Scenario: 拖分隔条

- **WHEN** 用户在「活跃任务」与「项目」之间拖动分隔条向下 80px
- **THEN** 「未完成」变高 80px、「项目」变矮 80px，其它子面板不动，两条内容都在各自区域内滚动

#### Scenario: 折叠一个子面板

- **WHEN** 用户点「主会话」子面板头部的折叠键
- **THEN** 该子面板只剩 34px 的标题行，箭头指向右，下面的「子代理」子面板上移补位

### Requirement: 任务页三段

任务页 MUST 是「调度行 + 开发子面板 + 验收子面板 + 停靠详情」，列表项三段式，MUST NOT 有列头。开发与验收 MUST 是两个可折叠、可拖高度的子面板（见「子面板」）。

- 调度行 MUST 是一行：状态点 + 巡检间隔 + 并发 + 上次成功时间。
- 开发每项：状态点 + 任务名（等宽后缀写 `仓库/编号`）+ 右侧状态词；悬停右侧换成「暂停 / 停止 / 更多」。
- 验收每项：状态点 + 批次号（等宽）+ 右侧进度（`1/2`）；悬停右侧换成「打开 / 更多」。
- 选中项的详情 MUST 是第三块子面板（头部写「详情 + 任务名 + 状态」，右端带暂停/更多），MUST 可折叠、可拖高度；列表 MUST 始终可见。

#### Scenario: 一条开发任务

- **WHEN** 渲染开发列表
- **THEN** 每行是「状态点 + 任务名 + 仓库/编号 + 状态词」，没有列头

#### Scenario: 验收进度

- **WHEN** 某批次通过 1 个、共 2 个
- **THEN** 该行右侧写「1/2」

### Requirement: 任务的创建与行内动作

开发段 MUST NOT 提供「新建任务」按钮：任务由调度（子代理计划）创建，面板不是创建入口。MUST NOT 在段头放任何创建类动作。

行内动作 MUST 分两层：

- **批量**：工具栏右端两个 28px 图标键（删除、发起验收），点击进入选择模式，选中后底部确认条写数量与不可用原因。
- **单个**：行悬停时在行尾（状态列右侧的 22px 动作列）出现 `⋯`，菜单里至少有「暂停 / 停止 / 删除任务」。单个删除 MUST 与批量删除一样保留分支、清理引用。

悬停时右侧自定义区域 MUST 由「指示灯 + 状态词」换成操作键（状态词让位给操作），移开后 MUST 换回状态词；MUST NOT 为了补偿而在行首图标位再放一枚状态灯——图标位只表达结构。

#### Scenario: 开发段没有创建入口

- **WHEN** 用户打开任务页
- **THEN** 开发段头只有「开发 5」，没有「新建」按钮；工具栏右端只有批量删除与批量发起验收两个图标键

#### Scenario: 单独删除一个开发任务

- **WHEN** 用户把鼠标移到某条开发任务行上
- **THEN** 行尾出现 `⋯`，点开有「暂停 / 停止 / 删除任务」，选删除后该行消失，同一任务的分支被保留

### Requirement: 任务行的图标与子任务位置

任务行（开发、验收、调度）的行首 MUST 是同一个文档图标（圆角页 + 右上折角，16px、1px 线宽、圆头），**不区分有没有子任务**，MUST NOT 用展开/收起箭头、MUST NOT 用「文档 + 加号/减号」角标。

列表 MUST NOT 就地展开：任务行与验收批次行都只有一行，MUST NOT 在行下插入子项行、MUST NOT 出现子项缩进。子任务（开发任务的依赖、验收批次包含的开发任务）MUST 全部在「详情」子面板里列出：标题 + 状态，可点进那条子任务自己的详情。

#### Scenario: 有依赖的任务

- **WHEN** 用户看「槽位清理」这一行
- **THEN** 行首是文档图标，行下没有任何子项；点开这行的详情，详情里有一段「依赖 2」，列出「登录态接口」「基线合并策略」及各自状态

#### Scenario: 验收批次

- **WHEN** 用户看一个包含两条开发任务的验收批次
- **THEN** 行首是文档图标、右端显示 `已通过数/总数`；点开后详情里列出这两条开发任务，列表里不展开

### Requirement: 任务筛选

任务筛选 MUST 是页级工具栏里的四个 `Pill`：全部、待验收、开发中、更早，且只作用于任务行。筛选为待验收时，开发段只留待验收任务、验收段只留未通过批次、调度段折成一行计数；筛选为开发中时只留开发中任务；筛选为更早时只留已结束的开发任务与已通过批次。被筛空的段 MUST 保留段头与计数，不得整段消失。

#### Scenario: 选待验收

- **WHEN** 用户点「待验收」
- **THEN** 开发段只剩待验收任务，验收段只剩未通过批次，调度段折成一行计数，三个段头仍在

#### Scenario: 选更早

- **WHEN** 用户点「更早」
- **THEN** 只显示已验收、已合入、已停止、已放弃的开发任务与已通过的验收批次

### Requirement: 批量删除与发起验收

任务页默认 MUST 不显示勾选框。工具栏右端 MUST 是两个 28px 图标键：批量删除与发起验收，各自在可进入时可用。进入某个模式后每行才出现 `Checkbox`，不可操作的行勾选框置灰并给出原因，图标键与底部确认条都显示已选数量，再点同一图标或点取消退出。确认条 MUST 固定在内容区底部，写清数量与不可用原因。

#### Scenario: 进入发起验收

- **WHEN** 用户点发起验收图标
- **THEN** 每行出现勾选框，待验收且不在其它批次里的行可勾选，底部出现「发起验收」确认条

#### Scenario: 按钮不可用

- **WHEN** 已勾选两行，但涉及的某个验收槽位正在占用
- **THEN** 确认条里的 primary 按钮禁用，并在同一行写明槽位被占用

#### Scenario: 只作用于开发段

- **WHEN** 处于批量模式
- **THEN** 只有开发段的记录行出现勾选框，调度段与验收段不参与选择

### Requirement: 任务详情展开

点选一条任务 MUST 在面板下半屏出现停靠区，MUST NOT 展开成行内详情、也 MUST NOT 弹窗。

- 停靠区头部 MUST 是「详情 + 任务名 + 状态」+ 右侧操作键。
- 内容 MUST 是 24px 的键值行：槽位、分支、基线、用量；用量一行写完「61.4k　入 42.1k　出 19.3k」。
- 下面是改动文件清单：路径（等宽）+ 增删两列定宽右对齐，列表与详情 MUST 用同一套颜色。

#### Scenario: 点一条开发任务

- **WHEN** 用户点「面板三段重构」
- **THEN** 下半屏停靠区显示它的槽位、分支、基线、用量与 3 个改动文件，列表仍在上面

### Requirement: 槽位页

槽位页 MUST 每个仓库一个子面板，MUST NOT 是表格。

- 子面板头部 34px 就是仓库行：仓库图标 + 仓库名 + 右侧一行元信息，按「当前分支 → 干净或 N 处改动 → 空闲 N → 未建立 N」写；多个仓库之间可以用分隔条拖高度、单独折叠。
- 槽位项：编号（等宽 10、20px 图标位）+ 任务名（等宽后缀写该任务的分支）+ 右侧状态词；悬停右侧换成「打开」。
- 空闲与未建立 MUST 折成一条安静的行（全部 tertiary、无操作），MUST NOT 逐条铺满。
- 验收槽位 MUST 是同一列表里的项：编号 + 「验收 <批次号>」+ 右侧 已通过 / 未通过；未建立 MUST 保留一行「验收未建立」。

#### Scenario: 一个仓库只用了一个槽位

- **WHEN** 某仓库 4 个开发槽位只有 1 个在用
- **THEN** 组块右侧写「空闲 3」，列表里是这条在用的槽位 + 一条「空闲 3 个槽位」的安静行

#### Scenario: 验收还没建

- **WHEN** 某仓库还没发起过验收
- **THEN** 列表最后一行写「验收未建立」，右侧写「未建立」，没有端口

### Requirement: 基线页

基线页 MUST 是若干子面板：每个基线组一块，编辑/新增的弹窗也 MUST 是同一套子面板（最后一块，可折叠、可拖高度），MUST NOT 用固定停靠区或浮层对话框。

- 子面板头部 34px 就是组行：编号砖 + 组名 + 右侧「N 个项目」+ 编辑键。
- 成员项：仓库砖 + 仓库名（等宽后缀写该项目的分支）+ 右侧合并位置（根目录检出 / 基线槽位 / 被占用 / 槽位缺失）；悬停右侧换成「编辑 / 删除」。
- 合并位置 MUST 是纯文字，异常 MUST 用第二行的方式说明原因（写进详情或编辑区），MUST NOT 在行内再加一段。
- 点编辑或新建 MUST 追加一块「编辑 / 新建」子面板：头部写「编辑 + 组名 + 编号」或「新建」，表单里名称一行，下面每个项目一行 = 勾选框 + 仓库名 + 该项目自己的分支选择器；未勾选写「未选中」且不可选；出错项目的选择器标红，底部一句错误。

#### Scenario: 编辑一组基线

- **WHEN** 用户点某组的编辑
- **THEN** 停靠区出现表单，每个项目一行、行内带它自己的分支选择器

#### Scenario: 分支已不存在

- **WHEN** 某项目选中的分支在工作区不存在
- **THEN** 该项目的选择器标红，底部写「保存失败：分支 hotfix/pay 已不存在」，保存键禁用

### Requirement: 代理页

代理页 MUST 是「三个数字 + 主会话子面板 + 子代理子面板」：主会话与子代理各是一个可折叠、可拖高度的子面板（三格数字不参与分区）。

- 数字 MUST 是 `2/5 运行中`、验收中、空闲三格。
- 主会话项 MUST 只有一行：砖 + 「只做调度，每 30 秒巡检」+ 右侧「不计入」。
- 子代理项：代理砖 + 名字（后面跟「开发 / 验收」）+ 右侧用量（等宽数字）；验收代理 MUST 在名字里写批次号。
- 空闲代理 MUST 保留一行，名字降为三级墨色，后缀写「上一任务 X」，右侧不写用量。

#### Scenario: 两个代理在跑

- **WHEN** 两个子代理正在工作
- **THEN** 每行是「代理砖 + agent-N + 类型 + 用量」，空闲的两行在下面且更淡

### Requirement: 会话开关

工作流开关 MUST 注册在 `conversation.session.header.utilities`，使用共享 `Switch`，只出现在根会话，默认关闭，状态按会话保存在 `.dev-flow/state.json`。关闭 MUST NOT 删除槽位、分支或历史，也 MUST NOT 中断正在运行的子代理；关闭期间不得分配槽位、拉起子代理，面板上的发起验收 MUST 不可用并给出原因。

#### Scenario: 关闭开关

- **WHEN** 用户在有任务运行的会话里关掉开关
- **THEN** 开关变为关闭，正在运行的子代理继续运行，面板内容不变，发起验收变为不可用

#### Scenario: 切换到另一个会话

- **WHEN** 用户切到一个从未打开过工作流的会话
- **THEN** 开关显示为关闭，不继承上一个会话的状态

### Requirement: 加载、空与错误

首屏 MUST 用行级 skeleton，页面级等待才用居中 spinner，一个页面 MUST 只用一种加载表现。局部失败 MUST 在原位显示 notice 与重试，并保留已渲染的数据。只有整块数据为空时才允许居中显示空状态：一行 13px `label-tertiary` 文本加一个 primary 按钮。瞬时成功或失败 MUST 用全局 `Toast`，pending 状态 MUST NOT 弹 toast。

#### Scenario: 刷新失败

- **WHEN** 刷新时读取 `.dev-flow/` 失败且页面已有数据
- **THEN** 原数据保留，顶部出现一行 notice 与重试键

#### Scenario: 删除失败

- **WHEN** 删除一条任务失败
- **THEN** 该行仍留在列表里，并弹出失败 `Toast`
