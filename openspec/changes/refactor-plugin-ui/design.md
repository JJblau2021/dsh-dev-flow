## Context

面板现有的视图层是 2024–2025 年间长出来的：`src/client/pages.tsx` 1887 行把五页、格式化、交互状态和布局混在一起，`src/client/sheet.ts` 520 行用手写 CSS 定义了一套 `df-*` 设计系统（`df-card`、`df-metrics`、`df-kicker`、`df-hover-card`、`df-review-native-select`、`df-icon-btn`、`df-menu-item`），`src/client/vendor/FileDiff.tsx` 又是一份自绘的双栏 diff。三处加起来等于在 DSH 里另起了一套组件库——本次只拆前两处，`FileDiff` 随 Diff 页一起维持现状。

DSH 侧的约束非常具体：右侧栏面板"是页面的一列，不是盖在页面上的卡片"，pane body 没有 padding、没有 header 行；浅色主题下 `--dsw-alias-bg-layer-1|2|3` 三个值全是纯白（`design-platform.css:181-183`），所以"用卡片分层"在浅色下根本没有视觉依据，只是多了一圈描边；`dsh-client-ui-ux` 技能明令 feature CSS 字重 ≤500、不得复制已有控件、悬停样式必须包在 `@media (hover: hover)` 里。`需求.md:261-356` 也已经把这条写成硬性要求：不得自创配色、圆角、间距与卡片样式。

功能逻辑侧已经稳定：任务状态机九态、调度并发、验收批次、基线组、槽位目录、`settings.json` 九项、RPC 方法表都在 `kernel/` 里，与视图无关。所以这是一次纯视图重写，风险集中在前端。

面板可用宽度 320–560px，不是全页。这是所有布局决策的前提：信息必须一行一条，不能横向铺开。

## Goals / Non-Goals

**Goals:**

- 五个页面与会话开关换成 DSH 原生语言，观感与文件树、插件页同源。
- 让"层次"由 0.5px 细线、墨色分级与留白承担，删掉全部自绘卡片材质。
- 每个功能点都能指到具体的内置组件，插件代码里不再有可交互的自绘控件。
- 视图层重新分层：数据读取、格式化、页面组件各自独立，单文件回到可读规模。
- 后端零改动，`.dev-flow/` 状态文件格式不变，旧数据直接可用。

**Non-Goals:**

- 不改任何调度、验收、合并、依赖、槽位分配的逻辑与文案语义。
- 不做任务页的拖拽换序、段高记忆。
- 不改 Diff 页与设置页：两者维持现状，不重画、不迁移组件（见 D2）。
- 不引入组件库、Tailwind、CSS-in-JS 或任何新依赖。
- 不做响应式断点系统：面板固定是窄列，只处理 320–560 区间。
- 不追求新插画或品牌元素，不加 logo、不加渐变、不加动效装饰。

## Decisions

### D1. 三段单滚动，而不是三块可拖拽面板

`功能清单.md` 12.3 要求调度/开发/验收三块各自独立、可拖拽换序、可拖拽高度、最小 120px、按 `dsh-dev-flow.task-panes` 记忆高度。在 320–560px 的一列里，这意味着三个嵌套滚动容器加一根可拖分隔条，用户要在三层滚动之间猜"我在滚哪个"，而且 DSH 里没有任何同类交互可以参照。

改为：三段在同一条滚动列里依次排列，段头 32px sticky，可折叠。顺序固定为调度→开发→验收，因为它对应"谁在跑 → 做什么 → 怎么收"的阅读顺序，不需要用户配置。

代价是失去"我想先看验收"的自由。缓解：段头可折叠，且筛选"待验收"会把视线直接带到验收段。收益是不再有一份需要迁移和容错的高度状态，也不会出现"上次拖到 120px 的段里塞不下一条任务"。

备选：保留拖拽但只允许换序不调高。否决，因为换序后仍然需要记住顺序，状态没少，交互复杂度却还在。

### D2. Diff 页与设置页不在本次范围

Diff 页现有实现是 `diff-tab.tsx` + `vendor/FileDiff.tsx`（自绘双栏）加 `sheet.ts` 里的 `df-review*` 类；设置页是插件详情页里的 `SettingsForm`，走 `plugins.bundle.config`，本身已经落在 DSH 的位置上。

三种选择：① 一并重写成 `DiffBlock` 代码卡；② 只换视觉、保留双栏；③ 不动。用户在看过 Diff 重写稿后判定"效果是错的，diff 页和设置都不用改，使用现状即可"，于是取 ③。

代价与约束：

- `sheet.ts` 不能删——Diff 页仍依赖它的 `df-review*` 类。清理策略改为"面板不再引用 `df-*`"，`sheet.ts` 留到 Diff 页重做时一起删。
- 面板重写不能把 `SettingsForm` 一起删：它当前定义在 `pages.tsx:1381`，重写 `pages.tsx` 时必须原样保留（或抽到独立文件），行为与 RPC 调用不变。
- 因此本 change 的"零自绘控件"目标只对五个面板页与会话开关成立，Diff 与设置是已知例外。

### D3. 概览用「三主数 + 一行元信息」，而不是六格指标表

六个数字并不等价：子代理占用、活跃任务、待验收决定用户下一步动作，项目数、活跃槽位、基线条数只是背景。六格等权表格会把主次抹平，而格子线又把它们切成一堆小方块。

改为：三个 20/500 主数字（标签 12/18 `label-tertiary`），其余三项压成主数字下方的一行 12px 元信息，用 `·` 分隔；下面接项目筛选 `Pill`、项目行、未完成任务行。零边框、零格线、零卡片。

代价：不再是一眼可比的同质矩阵。收益：注意力按决策价值分配，且整块区域不需要任何线条。


指标区承载在本页唯一的 R12 底色块里（`bg-module-platform`）：没有块时三个数字像浮在空白里，有了块才有「这一页被谁守着」的锚点；这也替掉了原来「三张指标卡」的盒子感——一块而不是三块。

### D4. 状态点管进程，`Tag` 管业务结论

功能清单要求状态有文字标签。若每个状态都配 `Tag`，一行里会出现"点 + 状态词 + Tag"三重表达。规则：`StateDot` 表达进程位置（六种），`Tag` 只在需要强调业务结论时出现（失败 `danger`、待合入 `info`、已合入 `success`），其余状态只留点与 13px 文本。

`StateDot` 的 `appearance="step"` 不用于任务行：它是为 checklist 设计的空心圆，语义是"还没做"，与"waiting"冲突。

### D5. 直接 `import` primitives，删掉 `loadUi()` 运行时探测

现在的 `ui.tsx` 用 `require()` 探测 primitives，失败就退回原生 `<button>`。这正是旧 UI 走形的根因之一：降级路径没人测，一旦探测失败，界面在"半个 DSH"和"原生控件"之间摇摆。

改为：静态 `import`，缺失即在插件加载期报错。运行版 0.2.2-rc.5 的 shell bundle 里已有完整导出表，`client.js` 现在也在用同一通道，风险低。这一步先做一个最小 spike 验证（见 Open Questions）。

### D6. 会话开关迁到 `conversation.session.header.utilities`

`需求.md` 已写明开关应挂在会话头部工具栏，只根会话显示。注册为 `kind: 'list', scope: 'session'` 的项，用共享 `Switch`，标签文案走 `locale.ts`。关闭只影响"分配槽位 / 拉起子代理 / 发起验收"，不中断已在跑的子代理，也不动任何数据——这条现有后端已经满足，视图只需把条件下发。

### D7. 设置页原样保留

设置页已经挂在插件详情页的 `plugins.bundle.config` 上，用 `SettingsForm`，六项字段、两级模型选择、staged draft、离开丢弃都由它处理，位置与组件选择都符合规范。既然用户判定设置"不用改"，本 change 只做一件事：重写 `pages.tsx` 时把它原样保留（可以抽到独立文件，但不改行为、不改文案、不改 RPC）。

### D8. 数据只读一次，五页共享，不轮询

面板挂载时读一次快照（`.dev-flow/state.json` + 仓库扫描结果），五页共用同一份内存数据；点刷新再读一次；页面切换不重读。所有写操作后由后端返回新快照或由前端重新读取一次，不做乐观更新。

理由：仓库扫描要遍历 `.git`，代价不低；而工作流的变化几乎都由用户自己的操作驱动，轮询收益极低。功能清单也明确要求手动刷新。

### D9. 视图层拆成四层

- `client/data/`：快照读取与派生（活跃数、分母、排序、分组、格式化），纯函数、无 JSX。
- `client/components/`：本插件复用的少量组合件——记录行骨架、段头、指标格、确认条、空状态。全部由 primitives 组合，不含颜色。
- `client/pages/`：五个面板页，只做布局与交互接线。`DiffPage` 与 `SettingsPage` 不在本次范围。
- `client/locale.ts`：全部文案。

面板相关样式改为每层各自的 `*.module.css`，只允许 `--dsw-*`/`--dsh-*` 变量；`sheet.ts` 因 Diff 页沿用而保留，但五个面板页 MUST NOT 再引用它的类。

### D10. 五段导航在 320px 下的处理

五个双字标签加 8px 内边距，整排约 250px，320px 的面板里放得下，无需容器查询，也无需在窄屏把文字换成图标（换图标会让五个页名都变成猜谜）。真正要守的是别加分隔符或竖线——那会在 320px 下把 250px 撑成 300px。

骨架（320px 时唯一的变化是导航右端的刷新键仍然保留，行内间距不变）：

```
┌──────────────────────────────────────────────┐
│ 概览  任务  槽位  基线  代理            ↻     │  38px
├──────────────────────────────────────────────┤
│ 全部  待验收  开发中  更早        ⧉   ✓       │  34px  (任务页才有)
├──────────────────────────────────────────────┤
│ 调度 · 1                                     │  32px sticky
│ ● 等待依赖  api 重构登录态接口               │  44px
│                                              │
│ 开发 · 5                                     │
│ ▶ ● 登录态接口    api   封存于 | 待验收      │  52px
│ ● 失败 支付回调重试  pay  3 个文件     ⟳     │
├──────────────────────────────────────────────┤
│ 已选 2 项 · 2 个验收槽位被占用    [发起验收]  │  52px 确认条
└──────────────────────────────────────────────┘
   ↑16                                        ↑6
```

### D11. 层次靠「列网格 + 停靠区」，不靠线、卡、带、缩进

这条被推翻了五次，每次的理由都记在这里，因为它们共同指向同一个结论：**在 400px 宽的面板里，能稳定承担结构的只有对齐。**

1. **横线**：每个段、每行都画 0.5px，整屏是横线（用户：不喜欢分割线）。
2. **卡片墙**：改用卡后，浅色主题下 `bg-layer-1/2/3` 全是纯白，卡只能靠描边，于是又回到线；且一屏 4–5 张卡加砖加标签，所有元素同层级喊话。
3. **只靠间距**：加大组间距到 20px 仍读不出边界（用户："仅调大一些间距还是不够明显，看久了很累"）。
4. **竖轨 + 缩进**：用 0.5px 竖轨把组内行挂到仓库名下，用户："看着很敷衍"。
5. **区域带**：整幅底色带 + 12px 白缝，确实切出了区域，但整页压着一层灰，"看着很奇怪"。
6. **左侧固定标签列**：84px 标签列 + 内容列，结构最清楚的一版，但读起来像表单。
7. **表格骨架 + 段头 + 停靠区**（采用）：列头出现一次、列对齐、行高 30/44，段头只写标题与计数，详情固定在面板下半屏。

采用版的规则：

- 首列 16px 起，状态点或砖占 20×20，正文与列头都从 44px 起——五页共用这一条线。
- 中列 104px、右列 62px 右对齐、右缘 384px，任何一页都不许改列宽。
- 行 30px（单行）或 44px（标题 + 副行），列头 24px，段头 26px。
- 全页只有一个容器：停靠区，它只给自己的上沿一条 0.5px 线。
- 状态只有一种编码：行首 6px 点 + 右列状态词。

为什么网格胜出：它把"这是什么、属于哪、什么状态"三件事固定在三个 x 坐标上，读者不需要学新的容器语言，也不需要数间距；对齐本身产生秩序，不消耗任何颜色、线或底色。代价是：内容必须能被切成"标题 / 副行 / 右侧值"三段，塞不进这个形状的信息（依赖树、改动文件预览）只能进停靠区——这也是详情必须停靠的原因。

### D12. 页面导航不用 `SegmentedTabs`

`需求.md` 的组件映射写了 `SegmentedTabs size="sm"`。实做时它是"灰色胶囊 + 白色药丸"，而它的正上方正是 dockkit 的 pane 标签行；两行叠在一起，读起来是"标签栏的标签栏"，而且 400px 宽的容器里 5 段各 76px，灰色死区占了大半。这正是"顶部 tab 样式不好看"的来源。

改为：pane 标签按 dockkit 的 quiet 形态渲染（13px 主墨、无底、无关闭键——它本来就不可关闭），下面一行只放 13px 文本标签，选中项靠字重与墨色，其余退到 `label-tertiary`，靠 8px 内边距与 hover 填充提供可点面积。整屏只留一条 0.5px 缝在这行下面。

代价：没有滑动指示器，选中态只靠 500 字重与主墨，弱于胶囊；在 5 个中文双字标签下可读，但页数若增到 7 个以上就需要换形态（那时应改成菜单）。收益：顶部从 78px 降到 66px，一屏少一个"控件块"，与文件树面板的顶部同构。

备选（若仍想要胶囊）：`SegmentedTabs size="sm"` 收成 hug-content（`inline-flex`）而不是撑满 400px，把灰底限制在 260px 内。已否决——治不了"两层标签"的根因。

### D13. 每页一个焦点

一条可验收的密度规则，防止再回到"什么都有":

- 每页只有一个 20px 元素（概览与代理的主数字），或只有一个抬起块（任务详情），两者不同时出现。
- 每行最多三段信息：标识 + 标题 / 一行 12px 元信息 / 右侧一个值或一个动作。短 id 与时间移到展开详情，一行里不放两个 `Tag`。
- 空闲与次要对象合并：代理页的空闲代理收成段尾一行，槽位页的空槽位只写"空闲"。
- 停靠区与 22px 主数互斥，同页最多一处。
- 密度差异只允许通过行高与内容取舍实现，不允许整体缩字号或缩 gap。

代价：信息密度下降，需要点击展开才能看到的细节变多。收益：首屏能一眼看出"现在有几件事在跑、哪里出问题"，这恰好是本插件的主问题。

## Risks / Trade-offs

- **[primitives 导出与 rc.5 不一致]** → 开工前跑一次 spike：注册一个只有 `SegmentedTabs` + `Pill` + `Tag` + `StateDot` + `Switch` + `Menu` 的面板页，确认全部渲染。缺谁就用最接近的替代，不自己补。
- **[`conversation.session.header.utilities` 的可见性与权限]** → 先验证槽位存在与 `kind`/`scope` 语义；若头部工具栏在窄窗口会溢出，改为在 panel 页头放开关，并在设计里记录这一偏差。
- **[五段导航在 320px 拥挤]** → D10 的容器查询兜底；再不行就只留图标加 `Tooltip`。
- **[三段单滚动后"开发中"的任务被压到很下面]** → 段头 sticky 加筛选承担定位；"待验收"筛选会把验收段顶上来。
- **[删除 `sheet.ts` 导致视觉回退到"没有样式"的裸控件]** → 每个页面先定骨架再填内容，骨架数值直接取 `FilesBody.module.css` 与 `UiRadius` 的角色表，不凭感觉调。
- **[六格指标在 320px 换行不齐]** → 固定两列，窄屏仍两列，数值字号允许降到 16/24，不改成三列。
- **[即时反馈被误做成行内文案]** → 统一用挂 `shell.overlay` 的 `Toast`；行内只放"需要重试的失败"。
- **[与 `需求.md` 任务页单列表的表述冲突]** → 本设计采用三段，但用"开发任务和验收任务仍然分行"满足其原意；实现时以本 change 的 spec 为准，并回头同步 `需求.md`。

## Migration Plan

1. **Spike（半天）**：最小页面验证 primitives 导出、`sidebar.right.pane.tab` body 的 padding 假设、`header.utilities` 槽位。
2. **数据层**：抽出 `client/data/`，把 `pages.tsx` 里的派生逻辑搬过去，附单元测试。
3. **骨架件**：记录行、段头、指标格、确认条、空状态，每个都用玩具数据在面板里看效果。
4. **逐页替换**：概览 → 任务 → 槽位 → 基线 → 代理。每页替换后即删掉旧实现，避免两套并存；Diff 与设置保持现状。
5. **删旧**：`pages.tsx` 里面板相关的 `df-*` 用法与旧页面代码；`plugin.tsx` 里 `loadUi` 与 `UiKit` 一并移除。`sheet.ts`、`diff-tab.tsx`、`vendor/FileDiff.tsx` 因 Diff 页沿用而保留。
6. **收尾**：`locale.ts` 补齐与去重；重拍 `docs/images/panel-*.png`；跑 `npm test` 与 `node scripts/build.mjs`。

回滚：本次只动 `src/client/` 与构建产物 `client.js`，回滚即 `git checkout src/client client.js`。后端与状态文件不受影响，所以不存在数据回滚。
